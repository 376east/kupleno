# Работа над Куплено

## Сначала контекст и координация

Прочитай [README](README.md), [PLAN](PLAN.md) и [документацию предпросмотра](docs/PREVIEW.md). Основная разработка идёт в `extension/next`; прежняя реализация рядом нужна для совместимости и сравнения. Не переносить изменения между ними вслепую.

Перед работой: `git status --short`, `git fetch origin`, просмотр актуальных веток, открытых issues и PR. При наличии `gh`: `gh issue list`, `gh pr list`. Если CLI не авторизован, используй доступный GitHub API/интерфейс; не меняй глобальную авторизацию и git-конфигурацию.

У задачи должен быть один владелец, ожидаемый результат и границы файлов. Зафиксируй это в issue или описании PR до параллельной работы. Создай отдельную ветку на задачу. Проверь, что ту же часть уже не взял другой участник. При пересечении договорись о разделении; не перезаписывай чужие изменения.

## Коммиты и публикация прогресса

Владелец проекта разрешил обычные commit/push в рамках порученных задач этого репозитория. Это разрешение не распространяется на другие проекты, личные данные, force-push, удаление веток и автоматическое слияние чужой работы.

Делай частые осмысленные коммиты: после небольшого законченного проверенного изменения и перед передачей работы. После такой точки отправляй рабочую ветку на origin, чтобы прогресс был виден. Не коммить каждое нажатие и заведомо сломанную сборку. В PR укажи владельца, границы файлов, результат, проверки и оставшиеся ограничения. Для публичного текста используй простой русский, без отчёта о внутренней работе агента. Сначала просмотри diff и шаблон последних коммитов.

Не используй force-push, reset чужих коммитов и массовое `git add .` без просмотра набора. Не сливай PR самовольно. Новые функции из PLAN требуют отдельной задачи.

## Реализация

Сохраняй базу и неизвестные поля резервных копий. Деньги считай в целых копейках. Не объединяй покупки только по названию и сумме. Неполный сбор не должен стирать старую историю. Не логируй токены, cookie, полные приватные ссылки чеков. Не делай из фонового обработчика универсальный сетевой прокси.

Каждый сбор использует свою фоновую вкладку, не перехватывает фокус и не закрывает пользовательские вкладки. Изменяя сообщения worker/offscreen/UI, проверяй обе стороны контракта. [Контракт](extension/next/collection.ts), [браузерный тест](scripts/next-collection-smoke.cjs).

Не добавляй облако, аналитику или AI-провайдера без отдельного решения. Никаких секретов и реальных покупок в тестах/демо. Не загружай всю папку чата и локальное `work` на GitHub.

## Проверки перед передачей

После установки зависимостей выполни `npm run preview:check`. Если затронут интерфейс, хранение или сбор, выполни `npm run preview:browser`; при визуальных изменениях ещё `npm run preview:design` с `KUPLENO_DESIGN_OUTPUT`. Подготовка браузера описана в [PREVIEW](docs/PREVIEW.md#запуск).

Тесты со служебными ответами магазинов не подтверждают живую интеграцию. Не выдавай успешный PDF fixture за работающий аккаунт Ozon. Ошибку CI на своей ветке разбери, а не объявляй старой без проверки. Проверяй и собирай окончательный commit; после push проверь удалённый SHA и результат CI. Закрой созданные тестовые браузеры и серверы.

Для прежней реализации используются отдельные проверки из [TESTING](docs/TESTING.md). Публикация стабильного релиза идёт только по отдельной задаче и [RELEASE](RELEASE.md).
