# Безопасность Куплено

Куплено читает финансовую историю и использует уже открытые сеансы маркетплейсов, поэтому сообщения об уязвимостях нельзя публиковать вместе с токенами, cookie, чеками или резервными копиями.

## Как сообщить об уязвимости

Создайте приватный [GitHub Security Advisory](https://github.com/malyarq/kupleno/security/advisories/new). Не используйте публичный Issue до исправления.

Укажите:

- версию Куплено и браузера;
- затронутый маркетплейс;
- минимальные шаги воспроизведения;
- ожидаемое и фактическое поведение;
- возможное влияние;
- очищенный пример без персональных данных и секретов.

Не прикладывайте историю покупок, полный URL чека, cookie, токен, email, резервную копию или необработанный журнал.

## Сроки обработки

- подтверждение получения — до 7 дней;
- первичная оценка риска — до 14 дней;
- сроки исправления зависят от риска и изменений маркетплейса;
- публикация деталей — после доступности исправления или по отдельной договорённости.

## Поддерживаемые версии

Исправления безопасности выпускаются для последней опубликованной версии. Для предыдущей версии гарантируется только возможность отката по инструкции, если её формат данных совместим. Точные ограничения указаны в [документе о данных и совместимости](docs/DATA_AND_COMPATIBILITY.md).

## Границы доверия

- расширение не принимает внешние сообщения от других расширений или сайтов;
- доступ к маркетплейсам и cookie запрашивается только по действию пользователя;
- удалённый код не загружается;
- PDF.js поставляется внутри ZIP и проверяется по зафиксированным SHA-256;
- Semgrep CE проверяет исходники JS/TS при push в `main`, pull request и раз в неделю;
- история покупок не отправляется разработчику.

Подробнее: [PRIVACY.md](PRIVACY.md) и [архитектура](docs/ARCHITECTURE.md).

## Проверка исходников в CI

[CI](.github/workflows/ci.yml) запускает Semgrep CE 1.179.0 с закреплёнными правилами browser/lang security и React из [semgrep-rules](https://github.com/semgrep/semgrep-rules/tree/a84ff9cc2453ca91d581380de4b8b3f272f6f4be). Исходники обрабатываются на runner, облачный аккаунт Semgrep не используется; отправка метрик выключена. Находки и ошибки сканирования завершают проверку ошибкой. Отдельный небезопасный пример с eval обязан вызвать срабатывание. [Сценарий](scripts/security-scan.py).

Проверяются обе реализации в extension. Исключены зависимости, сборки и тестовые файлы с намеренно небезопасными HTML-образцами; сами тесты продолжают выполняться в обычном CI. Проверка поставляемого PDF.js по хешам сохранена. Четыре предупреждения detect-non-literal-regexp разобраны и подавлены только возле конкретных выражений: в legacy ключ экранирован, в двух новых обработчиках функция вызывается лишь с фиксированными именами заголовков. Причины указаны рядом с nosemgrep в коде.

В [прогоне CodeQL 4 октября 2026](https://github.com/malyarq/kupleno/actions/runs/37162422874) анализ выполнился, а загрузка результатов завершилась ошибкой `Code scanning is not enabled for this repository`. Недоступный workflow удалён; платные возможности не включались. Автоматическую проверку выполняет Semgrep CE.

Semgrep CE имеет более узкий анализ потока данных, чем CodeQL security-extended. Его зелёный результат не означает успешного CodeQL или отсутствия уязвимостей. Отчёты доступны в логах CI; при ручном запуске с `keep_artifacts` они дополнительно сохраняются на 14 дней. Это дополнение к тестам и ревью.
